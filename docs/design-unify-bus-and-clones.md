# 设计方案：一切皆广播、一切皆克隆体

> 状态：**设计稿**（未实施）。这份文档只回答「要做成什么样、为什么、怎么分步」，
> 代码一行没动 —— 按约定，架构级改动先出方案再动手。
>
> 涉及的现状引用都给了 `文件:行号`，可逐条对照核实。

---

## 0. 一句话

把现在**「一条总线 + 三条半特例」**收敛成**两条通用规则**：

- **规则 A（一切皆广播）**：运行时只认一件事 —— *在某个时刻，向某个频道发一条消息*。
  每帧阶段、按键、碰撞、点击、生命周期，都只是**事件源**；事件源负责「翻译」，总线负责「派发」。
- **规则 B（一切皆克隆体）**：项目里的每个实体都是**原型**；运行时里跑的每个实体都是**克隆体**
  （「原型自己那份实例」也算克隆体，只是它不是复制出来的）。

好处不是「更优雅」，而是**三边看到的是同一件事**：积木视图能订阅的，代码视图能写；
调试面板能显示的，就是总线上真实发生过的。

## 1. 现状：已经统一了一半

### 1.1 广播侧

订阅表本身**已经是统一的**：`Runtime._subByChannel`（`src/runtime/vm.js:107`、`buildSubscriptions` 191-223），
hat → 频道的映射在一处完成（`vm.js:206-212`）：

| 帽块 | 落到的频道 |
|---|---|
| 当 ▶ 被点击 | `_start` |
| 当收到 [频道] | 频道名（`update` / 自定义） |
| 当按下 [键] | `_key` |
| 当 [实体] 被点击 | `_click` |
| 当 [A] 碰到 [B] | `_collision` |
| 当作为克隆体启动时 | `_clone` |

**但派发侧是分开的**，而且是五条各写一遍的路径：

| 事件 | 谁派发 | 什么时候 | 单线程语义 | `muted` 生效 | 进 `channelStats` / 时间轴 | 受「停止全部」约束 |
|---|---|---|---|---|---|---|
| 每帧阶段 | `runPhase()`（`vm.js:352-391`） | step 内固定顺序 | ✅ `singleThread` | ✅ | ✅ | ✅ `halted` |
| 按键 | `_emitKeyEdges()`（`vm.js:1031-1039`） | `input` 相位之前 | ❌ | ✅（走 `_fire`） | ✅ | ✅ |
| 碰撞 | `detectCollisions()`（`vm.js:818-840`） | `update` 之后 | ❌ | ✅ | ✅ | ✅ |
| 点击 | `clickAt()`（`vm.js:1040-1056`） | **帧外**（视口鼠标事件直接调，`scene/viewport.js:46`） | ❌ | ✅ | ❌（压根不在 step 里） | ❌ |
| 克隆体启动 | `clone()`（`vm.js:843-866`） | **帧外**、克隆那一刻 | ❌ | **❌（绕过了 `_fire`）** | ❌ | ❌ |

三个能直接指出的、可以写成断言的具体问题：

1. **`_clone` 绕过了 `_fire`**：`vm.js:849-864` 把线程创建那段逻辑手抄了一遍。
   后果：「订阅状态设为 取消订阅」对克隆体启动不生效；时间轴上统计不到；
   执行出错时走的是另一套日志分支。同一份逻辑存在两处，就是「改了 A 忘了 B」的温床。

   *已实测（不是推测）*：给 `_clone` 的订阅项打上 `muted` 之后再克隆一次，脚本**照跑**：

   ```
   订阅 _clone 的项数 = 1 | clone 之后 计数 = 1
   setSubscribed(玩家, _clone, false) → 订阅项状态 = [{"ch":"_clone","muted":true}]
   静音后再克隆：计数 = 2      ← 该是 1
   ```

   注意：**今天从积木里点不出来**（`_clone` 不在「广播频道」下拉里），
   所以它是「潜在的语义漏洞」而不是用户能踩到的坑 —— 但一旦内部事件频道拿到入口，
   它立刻变成现网 bug。这也是为什么 A 规则要求「派发只有一条路」。
2. **点击是帧外派发**：`clickAt()` 从视口事件里直接被调用，所以它不参与帧预算、
   不受「停止全部」（`halted`）约束、不进时间轴的阶段统计 —— 而它在语义上和
   「当收到 update」是同一类东西。
3. **按键的「一帧一次」是隐式的**：`_emitKeyEdges()` 只在 `input` 相位前跑一趟
   （`vm.js:365`），`pressed` 由 `setKey()`（`vm.js:1021`）维护。
   所以 `physics_update` 一帧多次广播这条性质对按键**不成立**，
   但没有任何地方写明这条差别 —— 用户只能靠试。

> **写这份方案时顺手发现并修掉的两个真 bug**（都属于「同一个判定框/同一条路径」被写散的问题，
> 记在这里是因为它们正是本方案要根除的那类错误）：
>
> 1. `clickAt()` 读的是 `A.t` / `A.b`，而 `aabb()` 给的是 `bottom` / `top` ——
>    两个字段都是 `undefined`，比较**恒为 false**：点舞台上任何角色都不会触发「当被点击」，
>    且不报错、不警告。现在改用 `A.bottom` / `A.top`，`tools/test-core.mjs` 第 11 节钉住。
> 2. `aabb()` 没把「大小」算进去，而绘制（`viewport.js:217`）和编辑器拾取
>    （`viewport.js:74-76`）都按 `size/100` 缩放 —— 于是放大到 200% 的角色
>    「看着碰上了却穿过去」「点它点不中」。现在 `aabb()` 也按大小缩放，
>    绘制 / 拾取 / 物理 / 点击四处终于用同一个框。（模板项目所有实体 `size=100`，
>    所以这条改动对现有项目与全部测试都是行为等价的。）
>
> 顺带记一条**刻意不改**的：`clickAt()` 命中 z 序最上面那个实体后就返回，
> 若它没有「当被点击」脚本，点击就到此为止、不会穿到下面的实体 ——
> **这与 Scratch 一致**（Scratch 只对最上面那个角色跑脚本），保持。

另外，内部频道（`_key` / `_click` / `_collision` / `_clone` / `_start`）和用户频道
混在同一张表里：用户在「广播频道」面板里看不到它们，但它们确实在总线上
（`stepBroadcast('_click')` 是可行的调试手段）。**这说明「内部事件」与「用户频道」
应当显式分型，而不是靠下划线前缀暗示。**

### 1.2 实体侧

工厂**只有一个**（`spawnFromDef`，`vm.js:150-186`），这是好底子。原型与克隆体的差别只有：

```js
name: isClone ? `${def.name}#${Math.floor(Math.random()*900+100)}` : def.name,
isClone: !!isClone,
cloneOf: isClone ? def.name : null,
```

加上 `state.clones` 里记了个名字（`vm.js:847`）。脚本按引用共享（`scripts: def.scripts`），
hat 匹配靠 `entityName` / `protoName`（`_matchSub` `vm.js:429-442`、`detectCollisions` 里的
`protoName` 比对）。**这已经是「原型-克隆体」了**，但还差这些：

1. **克隆体没有指向原型的引用**：只有 `protoName` / `cloneOf` 两个字符串。
   「读一下原型的属性」只能按名字回查，而且回查的是**运行时实例**，不是项目里的定义。
2. **属性是拷贝，不是继承**（`vm.js:157-181` 逐字段复制）：改原型不影响已存在的克隆体。
   Scratch 也是快照语义，但这里**没写明**是「刻意的快照」还是「没做继承」——
   设计要把它明确下来（见 D1）。
3. **`parent` 字段运行时没人用**：IR 里有层级（场景视图能拖），但 `spawnFromDef` 完全忽略它。
   于是「克隆体挂在原型下面」这件事在编辑器里看得见、在运行时不存在。
4. **`state.clones` 只增不减**：`removeEntity()`（`vm.js:872-877`）不清理它，
   全靠 `cloneCount()`（`vm.js:841`）里的 `this.state.entities[n]` 兜住。
5. **上限算错了对象**：`if (this.state.order.length > 400)`（`vm.js:845`）——
   判的是「所有实体」，不是克隆体数。一个项目里原型多的时候，克隆体配额会被原型吃掉。

## 2. 目标语义

### 2.1 两个角色

```
事件源(EventSource) ──emit(频道, 载荷)──▶ 总线(总线队列) ──帧内派发──▶ 订阅者(hat)
   │                                            │
   ├ frame    : 阶段时钟（frame_start…frame_end） │  · 单线程语义
   ├ key      : 键盘边沿                          │  · muted / halted 统一生效
   ├ pointer  : 鼠标点击                          │  · 每帧预算 & 时间轴统计
   ├ physics  : 碰撞进入/离开                     │  · 事件排队，不插队
   ├ lifecycle: 克隆体诞生 / 消亡 / 切场景 / 停止   │
   └ user     : 自定义频道（积木里「广播 XX」）     │
```

**最关键的一条：把「帧外立即派发」改成「入队 → 帧内派发」。**
`clickAt()` 和 `clone()` 不再直接跑脚本，而是往队列里塞事件，由 `step()` 在
规定的相位统一派发。代价是点击/克隆的响应推迟到下一帧（≤16ms）；
收益是它俩从此自动获得单线程语义、停止语义、预算约束和面板统计 —— 这正是 Scratch 的行为。

### 2.2 需要拍板的决策

| # | 决策 | 取哪个 | 为什么 |
|---|---|---|---|
| **D1** | 克隆体的属性是「快照」还是「活继承」 | **快照**（默认），另给「读原型属性」的取值积木 | 活继承会让「克隆体之间互相干扰」变成难查的 bug，也和 Scratch 心智冲突。要改原型→显式写一条广播，让所有克隆体自己响应。可预测 > 省事 |
| **D2** | 原型自己那份实例算不算克隆体 | **算**（`isClone` 一律 true），用 `isPrototypeInstance` 区分 | 一元化之后「删除此克隆体」「克隆体上限」「当作为克隆体启动时」只需要一套规则。但 `克隆体数量` 要**保持不含原型实例**（与 Scratch 一致） |
| **D3** | 生命周期广播清单 | 新增 `_destroy`（克隆体消亡）与 `_scene`（切场景），保留 `_start` / `_clone` | 「一切皆克隆体」之后，消亡必须有广播，否则清理逻辑没地方挂（现在只能靠 `alive=false` 悄悄消失） |
| **D4** | 事件源清单 | frame / key / pointer / physics / lifecycle / user | 每个事件源只做「翻译成一帧里的一条消息」，不许自己执行脚本 |
| **D5** | 同类事件一帧内的顺序 | 保持「阶段顺序」不变；事件源挂到固定相位 | 按键 → `input` 前；碰撞 → `update` 后；点击/克隆/消亡 → 下一帧的 `lifecycle` 相位（排在 `frame_start` 之后、`input` 之前） |
| **D6** | 克隆体上限按什么算 | `克隆体数 > 上限`（默认 400），且上限进 `settings` | 现在的判定会把原型算进去；放进 settings 才能被项目分别配置 |

## 4. 分三期落地（每期都能独立验收）

### 一期：只收拢路径，不动语义

- `_clone` 走 `_fire`（删掉 `clone()` 里手抄的那段）
- `clickAt()` 改成入队，帧内派发；补上 `channelStats` / 时间轴
- 内部频道显式分型（`registry.js`），面板能看见

**验收**（每条都写成可运行的断言，且在动第一行代码之前先确认它**现在会失败**）

- `npm test`：「直接给 `_clone` 的订阅项打 `muted`（走运行时 API）之后，克隆体启动不再跑」
  —— 今天会失败（见 §1.1 的实测输出）
- `npm test`：「点过『停止全部』之后，`clickAt()` 不再派发」
  —— 今天会失败（`clickAt` 走帧外路径，`halted` 管不到它）
- `probe-player`：点一下实体，断言**下一帧**才生效（证明不再帧外执行）
- 时间轴里能看到 `_click` / `_clone` 的 subs 与耗时
- 已修的两条不要退化：`npm test` 第 11 节（点角色触发 / 判定框跟大小走）、
  `npm run bubble` 的 1b（点标签出值 / 点可编辑字段让路）

### 二期：补生命周期

- `_destroy` / `_scene` 两个频道 + 两个新帽块 + 解析注解
- 克隆体消亡时清订阅、清 `state.clones`

**验收**
- 冒烟：克隆 3 个 → 删 1 个 → 断言 `克隆体数量` 与 `state.clones` 都少 1
- 冒烟：`当作为克隆体被删除时` 里读 `self` 拿到的是那个克隆体（不是原型）
- 冒烟：切场景广播一次，且顺序在 `frame_start` 之后

### 三期：原型-克隆体一元化

- `spawn(proto, over)`：唯一的实例化入口，原型实例也走它
- `proto` 对象引用 + `isPrototypeInstance` + 上限按克隆体数（进 `settings`）
- `parent` 要么接进运行时（克隆体挂到原型下），要么从 IR 里删掉
  —— **不允许继续「编辑器看得见、运行时不认」**

**验收**
- 冒烟：断言「原型实例 `isClone === true` 且 `isPrototypeInstance === true`」
- 冒烟：断言「`克隆体数量` 不含原型实例」
- 冒烟：上限改成 2 → 克隆 5 次 → 只有 2 个克隆体（原型不计入）

## 5. 兼容与风险

| 风险 | 处理 |
|---|---|
| 已保存的 `.dfp` 项目 | 无需迁移：`state.*` 是运行时的，不入项目文件；IR 结构不变（除 `parent` 的去留） |
| `克隆自己` 之后**同一帧内**克隆体就开始跑（现在的行为） | 一期不改这条：`settings.lifecyclePhase` 默认 `'immediate'` 保持旧行为，新项目模板用 `'next_frame'`。**等一期跑通一轮再切默认值** |
| 点击延迟一帧 | 与 Scratch 一致；在 README 的「已知取舍」里写明 |
| `克隆体数量` 的数值 | D2 决定后语义不变（仍不含原型实例），不需要改积木 |
| 性能 | 入队/出队是数组 push + 每相位一次 shift 扫描，参照现有 `_flushYield()`（`vm.js:651`）的量级；`npm run smoke` 里有 52 项真机断言兜着 |

## 6. 明确不做

- **不改积木形状和配色**：和 Scratch 一样是硬约束（`theme.js` 里是官方分类色）。
- **不做 Actor / ask-response 消息邮箱**：只做**单向广播**。需要「等一个结果」的场景用
  `广播并等待`（已有）表达。
- **不做真并发**：仍然是单线程协程 + 协作式让出（`_drive` / `frameYield`）。
  「一切皆广播」不是「一切皆线程」。
- **不做 ECS 数据导向重构**：实体保持对象形式 —— 调试时能在控制台里直接看，
  比缓存友好的数组布局重要得多。
- **不给内部频道开用户入口**：它们是事件源的产物，用户能订阅的仍然只有
  「阶段 + 自定义频道 + 六个帽块」这套语义。

## 7. 怎么知道做对了

三条通用判据（比任何单项断言都重要）：

1. **同一条规则能解释所有情况**：问「按键算不算广播」时，答案不该是「算，但它走别的路径」。
2. **每一处特例都能被删掉**：一期之后，`clone()` 里不应再出现线程创建代码。
3. **面板不撒谎**：广播时间轴里看到的调用次数与耗时，要和实际派发一一对应；
   看不见的派发就是 bug。
